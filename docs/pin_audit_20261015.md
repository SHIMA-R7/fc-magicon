# GPIO受動監視と固定パターン読み書き

ユーザー依頼：全ピンが正常か調べるテストプログラムを書き込み、実行する。

挿入状態でFCの出力へ対向駆動を加えるピンウォークや、未給電FCにプルアップを加える試験は行わない。`pin-audit-cold-fast-20261015.uf2` は既存NTストレス診断へ、GPIO入力値の受動サンプリングを追加する。監視は追加の方向・プル・出力設定を行わない。通常のCPUバス応答とミラーリング出力は診断プログラムの実行に引き続き使用する。

GPIO0～46のうちLED39を除く46本を監視し、各ピンでHigh/Lowを観測したか、連続サンプル間で値が変化したかを記録する。PSRAM CS47も監視対象外。観測はFC電源ON・バス開始後のNT試験中。サンプリングは各ピンのエッジを全て捉えるものではなく、低位/高位バンクの読み出しは同時刻の保証もない。エッジの時刻・周波数・電圧・正常性を測定するものではない。

NT診断はFC側で生成した13パターン、2バンク、2巡、4回読み戻しの52試験。描画・音声・動画ステージングなし。不一致位置・値・ビット別回数を記録する。初期値、固定出力、未使用線、今回の試験で励起していないアドレス線等は変化しない場合があるため、変化なし＝故障とは判定しない。GPIOが両値を観測しても、外部ピンの導通・隣接短絡・出力駆動能力が正常と証明するものではない。CHR表示の実時間応答も対象外。

ビルド：`build.ps1 -ColdBoot -FastReads -PinAudit`

UF2：`firmware/out-standalone-video/pin-audit-cold-fast-20261015.uf2`

SHA256：`491e90c7b2c4259010e51a0f1cd24382a845faf6f9ba7524fde5c05d2e4a1ab7`

検査：実C/6502の正常52試験、不良ビット固定、バンク別名接続の故障注入。最終単色表示のPPUアドレス復帰を修正し、修正後の正常・不良ビット検査を再実行した。GPIOマスクは低位/高位バンク、LED/PSRAM除外、値変化の累積を実Cで確認。GLOGとSLOGのUSB模擬入力も保存できることを確認。

FC OFFはユーザーが確認済み。BOOTSELのEF5E4EB554097CDFを確認後、上記UF2だけを書き込み、picotool照合OK。通常アプリへ再起動した。FCの電源ONはユーザー操作が必要で、現時点で実機診断の結果は未取得。

受信：`tools/read_nt_stress.py --port COM11 --timeout 180 --output <新しい結果.json>`

USBは全52試験完了または60秒の期限後に開始する。LEDは1回＝全試験合格、2回＝読み書き不一致、3回＝未完走／レポート異常。緑/赤の単色は診断終了表示で、動画は再生しない。

## 実機結果

ユーザー報告は「緑/一回」。USBから `pin-audit-hardware-20261015.json` と `.log` を取得した。status=2、全52試験完走、不一致0、全ビットの不一致0、メールボックス整合性異常0。各レコードの連番と署名も検査して一致した。CPU命令取得、FC自身で生成したパターンのNTへの書き込み・読み戻し、両バンクの使い分けが、この条件では成立した。

GPIOサンプル数26062096。GPIO0～38と40～43はHigh/Lowおよび変化を観測。44はHigh固定（音声動作なし）、45はLow固定（IRQ駆動なし）、46はHigh固定（FC電源ON）。これら3本は今回変化させていないので、出力機能や電源検出の切り替わりを合格と判定するものではない。モジュールLED39とPSRAM CS47は監視対象外。

この合格は全ピンの電気的な正常を保証しない。以前の動画診断とは、NTデータをFC側で生成すること、画面描画を止めること、VBlankごとの更新を使わないことが違う。したがって、特定GPIOや部品の恒久故障と断定する根拠は弱まる一方、CPUの$6000窓からのデータ取得、描画中のバス競合、VBlank転送、CHR応答などは追加の切り分けが必要。
