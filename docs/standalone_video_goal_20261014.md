# PC非接続・ツインファミコンでPVを自律再生する

ユーザー合意の当座の目標。対象はブルーアーカイブ7th PV（U6Wlb18KLrI）。
既存の保存済みsource.jsonによる原動画長は99秒。現時点で変換済みの素材は冒頭30秒のみ。
全編8fpsは将来の到達目標であり、動作確認済みではない。

## 保存形式と容量

転送用の15360Bフレームバッファをそのまま保存せず、PCで変換した
CHR4096B + NT1024B（属性64Bを含む）+ パレット32Bを1枚5152Bで保存する。
再生時のタイル探索・近似処理も不要になるが、PIO用32bit lookupへの展開と
非表示CHR/NTへのステージングは必要。これは画質改善ではなく同じ絵の事前変換。

音声は現在のPIO出力が8bitなので、ゲイン適用済みunsigned PCM8/32kHz/monoを保存。
PWM/PIOの出力とPC側16bit→8bit変換で丸め方式が異なる可能性はある。
独立した音質評価は未実施。

99秒・8fpsの見積り:

| 内容 | バイト |
|---|---:|
| 792枚 × 5152 | 4,080,384 |
| 99秒 × 32,000（PCM8） | 3,168,000 |
| ヘッダー | 64 |
| 合計 | 7,248,448 |
| 現行の素材領域（16MiBフラッシュの後半） | 8,388,608 |
| 残り | 1,140,160 |

同じ領域に既存ROMライブラリを併置できるという意味ではない。従来の転送形式と
PCM16のままでは同条件で約18.6MBになり、16MiB全体にも収まらない。

## 今回作成・確認したもの

`firmware/tools/pack_flash_video.py` は保存済み変換素材からFCPV v1を生成する。
シリアル通信・デバイス書込み機能は持たない。64Bヘッダーにバージョン、フレーム数、
fps分数、音声レート/サンプル数、領域オフセット、全長、本文CRC32を格納する。

`firmware/sim/standalone-video-20261014/pv-30s-4fps.fcpv` を生成済み。
全120枚を実際のC変換器で変換し、CHR/NT/属性/パレットから再構成したRGBが
quality-4fps-stableのexpectedと一致することを確認。ファイル再読込みとCRC照合も成功。
総サイズ1,578,080B、音声ゲイン20、クリップ0。実機への書込みは行っていない。

## 次の順序

1. FCPVの長さ・オフセット・CRCを検証し、フラッシュから先読みする自律再生ループを実装。
   USBを待つ経路を外し、PIO音声を再生時刻の基準にする。
2. 冒頭30秒・4fpsを現在の実機改善確認済みatomic表示/PIO音声へ接続する。
   ツインファミコンでPC非接続の電源ON・再生・終了を確認する。
3. NT1024Bの更新を現在の8VBlankから7VBlank以内へ短縮する。
   現行8VBlankはNTSCで約7.5fpsが上限なので、保存形式変更だけでは8fpsに達しない。
   最後のパレット更新・バンク反転を含めて6502のVBlankサイクル数を検証する。
4. PIOの実サンプルレートと音源レートの差を測り、長時間の音ずれを抑える。
5. 全99秒を変換・検証し、8fps全編へ進む。

## 起動と電源の未解決事項

先に作成したfastbootは独立したMapper0比較版であり、この再生機への統合は未実施。
150MHzの起動試験と、成功済み250MHzの映像/PIO音声はそのまま同一視できない。
PC非接続でもUSB充電器やモバイルバッテリーでRPを先行給電できる。
まずD1未実装の現在の配線でこの方法を試せる。FC本体だけから給電する場合はD1側の
経路を使うため、USB先行でRPが既に起動している試験と異なる。
ツインファミコンのリセット解除までの応答、RPのIOVDD立上り前のFC信号、電源断時、
USB併用時の逆流を測定する。OTPやソフトウェアだけで電気的安全性を保証しない。
