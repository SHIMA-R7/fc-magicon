# FC-MAGICON 仕様書(ハードウェア・ソフトウェア総合)

FC-MAGICON のハードウェア・ファームウェア・PC のソフトウェア・通信とデータの形式・試験の記録を 1 冊にまとめたもの。2026-09-27 時点。**基板 rev0.2 は発注済み・未着で、ファミコンの実機では未検証**。ファームウェアと PC のソフトは、PC の試験台(sim)と Core2350B2 単体(ピンヘッダーを付けたモジュール)で確かめた範囲まで。

[[TOC]]

## 1. 概要

ファミコン(HVC-001、本体基板 HVC-CPU-07)のカセットスロットに挿す自作カセット。Waveshare Core2350B2(RP2350B)1 個が、CPU のバスと PPU のバスの両方に直接応答する。FPGA は使わない。

| 機能 | 内容 |
|---|---|
| マジコン | フラッシュに書いた .nes を SRAM に写し、PRG(CPU 側)と CHR(PPU 側)を返す。マッパー 8 種類(4.6) |
| ゲーム選択メニュー | 何本もまとめて書き、起動時にファミコンの画面で選ぶ(4.10) |
| NSF プレイヤー | .nsf を本体の 2A03 で鳴らす。曲の切り替え・一時停止(4.7) |
| 画面転送(リモートデスクトップ) | PC の画面を 256 x 240 ドットでファミコンに映す。1コン = マウス、ファミリーベーシックのキーボード = PC のキーボード(4.8) |
| PC の音 | 画面転送中、PC で鳴っている音をファミコンの音声に混ぜて鳴らす(4.9) |
| Wi-Fi | ESP32-C6 を J6 につなぎ、画面転送を Wi-Fi で行う(5 章) |

### 1.1 全体の構成

| 所 | 部品・ソフト | 役目 |
|---|---|---|
| PC(Windows 11) | `remote_pc.py`・`pcaudio.py`・`nesframe.py`・`load_rom.ps1` など(6 章) | 画面の取り込みと変換、音の横取り、入力をマウス・キーへ、ROM の書き込み |
| 通り道 1 | USB(Core2350B2 の FPC-USB アダプター) | PC 直結。614KB/秒 |
| 通り道 2 | Wi-Fi → ESP32-C6(TCP ⇔ USB の素通し)→ J6 → RP2350(USB ホスト) | 無線。420KB/秒 |
| カセット | RP2350B(コア 0 = USB・画面転送・音、コア 1 = バスの応答)、PIO 3 つ | バスに応答、ROM・画面・音を出す |
| ファミコン | 2A03(CPU・音源)、2C02(PPU)、本体 RAM・VRAM | 6502 のプログラム(ゲーム、または FC-MAGICON が用意するドライバー)を動かす |

## 2. 動作モード

起動した時にフラッシュの ROM 置き場の中身で決まる。

| モード | 入り方 | カセットがすること | 本体の 6502 が動かすもの | USB(magicon) |
|---|---|---|---|---|
| ゲーム | `load_rom.ps1 game.nes`、またはメニューで選ぶ | PRG・CHR・WRAM を返し、マッパーを真似る | ゲーム | 1 秒ごとの様子を USB シリアルに |
| NSF プレイヤー | `load_rom.ps1 music.nsf`、またはメニューで選ぶ | 曲のデータとドライバーを返し、ベクターを横取り | NSF ドライバー($5000-)と曲 | 同上 |
| 画面転送 | `load_rom.ps1 -Remote`、またはメニューの REMOTE DESKTOP | PPU の読み出しに PC の絵を返す。音を鳴らす | 画面転送ドライバー($C000-) | 画面・音を受け、入力を返す |
| ゲーム選択メニュー | `load_rom.ps1 -Library フォルダー` | メニュー(NROM)をその場で組み立てて返す | メニュー($C000-) | 同上 |
| 試験画面 | ROM が無い・壊れている・対応していない時 | chr_test と同じ 4 色の縦縞 + 格子と音 | 試験 ROM | 理由を USB シリアルに |

別のファームウェア(`bus_test`・`chr_test`)は、基板が届いて最初に確かめる時だけ使う(4.1)。

## 3. ハードウェア

基板の詳しい所は `docs/hardware_spec_body.md` をそのまま取り込んでいる(3.1〜3.10)。3.11 は、モジュール単体の試験で使ったピン。

### 3.1 構成

| 経路 | 内容 |
|---|---|
| CPU バス(26本) | カセット端子 → Core2350B の GPIO0〜25 に直結(D0〜D7、A0〜A14、/ROMSEL、R/W、M2) |
| PPU バス | AD0〜AD7・A8〜A12 → GPIO26〜38 に直結。/RD・/WR・A13 → U2(74LVC245)→ GPIO40〜42 |
| ミラーリング | GPIO43 → JP1 → CIRAM A10(18番)。JP2/JP3 で PPU A10/A11 に固定もできる |
| /IRQ | GPIO45 → R4 → Q1 → /IRQ(15番) |
| 電源 | 本体 +5V(30・31番)→ D1 → Core2350B の VBUS → モジュール内 LDO → 3.3V → U2 |
| 本体 5V 検出 | +5V → R2/R3 分圧 → GPIO46 |
| 音声 | 45番 → R7(0Ω)→ 46番。GPIO44 の PWM → R9/C3 → VR1(音量)→ R8 → 46番。46番 → C4 → R10/R11 → J2(3.5mm ライン出力) |
| PC | Core2350B の USB(付属の FPC-USB アダプター)。同じ D+/D- を J6(予備ランド)にも出している |
| テスト | J4(カセット60ピン全部、端子の真上)、J5(内部信号)、J3(SWD)、TP1〜TP5 |

### 3.2 主要部品

| 記号 | 部品 | 役割 |
|---|---|---|
| U1(P1〜P4) | Waveshare Core2350B2 | RP2350B(QFN-80、GPIO 48本)、16MB フラッシュ、2MB PSRAM、LDO(ME6217C33)、12MHz 水晶。25.4mm 角、外周2列 64ピン |
| U2 | SN74LVC245AN(DIP-20) | PPU の /RD・/WR・A13 を 5V → 3.3V。5V 非トレラントの GPIO40〜42 へ渡す |
| Q1 | 2SC1815(TO-92) | /IRQ をオープンコレクタで引き下げる |
| D1 | 1N4001〜1N4007(ショットキー 1A 推奨) | 本体 5V → モジュールの VBUS。USB 給電時の本体への逆流を防ぐ |
| J1 | 基板エッジ(金メッキ端子 60本) | ファミコンのカセットスロット |
| J2 | PJ-324M | 3.5mm ライン出力(モノラルを L/R 両方へ) |
| VR1 | KOA KVSF637AC104(100kΩ、上面調整) | 拡張音源の音量。足は ①③ が 5.0mm 間隔、② がその中央の 5.0mm 上(データシートの推奨取付穴、φ1.2) |

### 3.3 電源

| 項目 | 値 |
|---|---|
| 供給元 | 本体の +5V(カセット端子 30・31番)。GND は 1・16番 |
| モジュールへの経路 | +5V → D1 → VBUS_MOD(モジュール P2-15 VBUS)→ モジュール内 LDO → +3V3 |
| VBUS_MOD の電圧 | 1N400x で約 4.3V、ショットキーなら約 4.6V(LDO の入力として十分) |
| +3V3 の使い道 | モジュールの 3V3 出力(P2-16)を U2 の電源と DIR に使う。C2 100nF をパスコンに |
| 平滑 | C1 10µF(VBUS_MOD) |
| USB 給電 | Core2350B の USB からも VBUS に入る。D1 があるので本体側の +5V へは流れない |
| 消費電流(見込み) | モジュール数十 mA 〜 100mA 程度(RP2350B のクロック次第)。本体の 7805 の範囲内 |

**逆流に注意**:USB だけで給電している時(本体の電源が切れている時)に RP2350B がバスへ出力すると、
電源の入っていない本体の IC に 3.3V が流れ込む。これを避けるため、本体の 5V を分圧して GPIO46 で監視する(3.6)。

### 3.4 バスの接続と電圧

**CPU バス(26本、すべて RP2350B に直結)**

| 信号 | GPIO | 向き |
|---|---|---|
| CPU D0〜D7 | 0〜7 | 双方向(読み出し時だけ RP2350B が出力) |
| CPU A0〜A14 | 8〜22(A0 から連続) | 入力 |
| /ROMSEL | 23 | 入力(= !(A15 & M2)) |
| R/W | 24 | 入力 |
| M2 | 25 | 入力 |

**PPU バス**

| 信号 | GPIO | 向き・経路 |
|---|---|---|
| PPU AD0〜AD7(カセット端子の PPU D0〜D7) | 26〜33 | 双方向。/RD が下がる直前はアドレス下位 8 ビット、その後データ |
| PPU A8〜A12 | 34〜38 | 入力。GPIO26〜38 で 13 ビットのアドレスが連続する |
| PPU /RD | 40 | U2 経由の入力 |
| PPU /WR | 41 | U2 経由の入力 |
| PPU A13 | 42 | U2 経由の入力(カセット端子 56番、非反転) |
| PPU /A13 | — | CIRAM /CE(48番)へ R1(0Ω)で直結。RP2350B にはつながない |
| PPU A0〜A7(ラッチ後) | — | RP2350B では使わない。J4 には出してある |

**電圧の扱い**

| GPIO | 5V を受けられるか | この基板での使い方 |
|---|---|---|
| 0〜38 | 可(IOVDD に電源が入っている時) | 5V のバス信号を直接受ける |
| 39 | 可 | モジュール上の LED(470Ω)が付いているので使わない |
| 40〜47(ADC 兼用) | **不可** | 40〜42 は U2(3.3V 電源の 74LVC245)の後。43〜46 は出力専用か分圧後の入力。47 はモジュール上の PSRAM の CS |

- RP2350B の出力は 3.3V。2A03・PPU(NMOS)の入力は H を 2.0〜2.4V 程度から認識するので受けられる。
- U2:DIR = +3V3(A→B)、/OE = GND(常に有効)。A 側(5V)に /RD・/WR・A13、B 側(3.3V)から GPIO40〜42。空き入力 A4〜A8 は GND。74LVC は電源が無い時も入力に 5V を受けられる。
- PIO は1ブロックで連続 32本しか扱えないので、CPU 用は GPIO0〜31、PPU 用は GPIO16〜47 の窓を使う。

### 3.5 PPU アドレスの読み取り方

ファミコンの PPU は、アドレス下位 8 ビットとデータを同じ 8本(AD0〜AD7)で時分割する。
本体側の 74LS373 がアドレスをラッチし、カセットには PPU A0〜A7 として出てくるが、この基板ではそれを使わない。

- PIO で「/RD が High の間、AD0〜AD7 を読み続ける」ループを回し、/RD が下がった時点で最後に読んだ値を下位アドレスとする。
- 上位は A8〜A12(と A13)を直接読む。
- PPU の読み出しは約 372ns ごと(PPU クロック 5.37MHz の 2 クロック)。/RD が下がってからデータを出すまでの余裕が足りるかは**未検証**(TP1・TP2 で測る)。
- 足りない場合でも、画面転送(FC-PICO 方式)・自作ゲーム・NSF には影響しない。市販の CHR-ROM ゲームの動作に影響する。

### 3.6 制御・周辺回路

**本体 5V の検出**

+5V → R2 15kΩ → FC_5V_SENSE(GPIO46)→ R3 22kΩ → GND。5V のとき 2.97V、4.75V のとき 2.82V。
ファームは GPIO46 が High になるまで、全てのバスのピンを入力にしておく。

**/IRQ**

GPIO45(IRQ_DRV)→ R4 4.7kΩ → Q1 ベース(R5 100kΩ で GND に引き下げ)。Q1 コレクタ → /IRQ(15番)、エミッタ → GND。
GPIO45 = High で /IRQ が Low(割り込み要求)。ベース電流は約 0.55mA。起動中は R5 で Q1 がオフ。
R6(10kΩ、+5V へのプルアップ)は未実装。本体側にプルアップがあることを確認済み。

**ミラーリング(CIRAM A10、18番)**

JP1〜JP3 のどれか1つだけをはんだで閉じる。

| ジャンパー | 18番につながるもの | 用途 |
|---|---|---|
| JP1 | GPIO43(CIRAM_A10_MCU) | ファームで切り替える(MMC1/MMC3 などのマッパー) |
| JP2 | PPU A10(53番) | 垂直ミラー固定 |
| JP3 | PPU A11(54番) | 水平ミラー固定 |

GPIO43 は 3.3V 出力。本体の VRAM が 3.3V を H と認識するかは実機で確認する。駄目なら JP2/JP3 を使う。

**音声**

| 部分 | 回路 | 値 |
|---|---|---|
| 素通し | 45番(本体からの音声)→ R7 0Ω → 46番(本体へ戻す) | 市販カセットと同じ |
| 拡張音源 | GPIO44 PWM → R9 1kΩ → EXP_AUDIO_RC(C3 10nF で GND)→ VR1 100kΩ(①=RC、③=GND、②=中点)→ R8 47kΩ → 46番 | RC の遮断周波数 約 15.9kHz。VR1 で音量 0〜最大。どこに回しても本体の音声ラインには 47kΩ 以上が付く |
| ライン出力 | 46番 → C4 10µF(+ 側が 46番)→ LOUT(R10 47kΩ で GND)→ R11 100Ω → J2 | 低域の遮断 約 0.34Hz。J2 は L/R に同じ信号 |

**操作**

| 部品 | 動作 |
|---|---|
| SW1 BOOTSEL | 押しながらリセットすると RP2350B が USB 書き込みモードになる |
| SW2 RESET | RP2350B の RUN を GND に落とす。**本体のリセットではない**(本体はリセットボタンで) |

### 3.10 ファームウェアが守ること

1. **起動時は全バスピンを入力**にし、GPIO46(本体 5V 検出)が High になってから出力を許す。
2. CPU D0〜D7 を出力するのは、読み出しサイクル(/ROMSEL = Low かつ R/W = High、または $6000〜$7FFF の WRAM 読み出し)の間だけ。
3. PPU AD0〜AD7 を出力するのは、/RD = Low かつ A13 = Low(パターンテーブル)の間だけ。A13 = High(ネームテーブル)の時は本体の VRAM が出力する。
4. RP2350 のエラッタ E9:バスのピンで内部プルダウンを使わない。
5. GPIO39(LED)・GPIO47(PSRAM CS)をバスに使わない。
6. /IRQ は GPIO45 = High で要求、Low で解除。
7. 電源投入直後は本体の CPU が RP2350B の起動を待たずに動く。間に合わなければ本体のリセットボタンを押す。


### 3.11 モジュール単体の試験で使ったピン(2026-09-27)

基板が届く前に、Core2350B2 にピンヘッダーを付けて試した時のつなぎ方。ピンの番号は `kicad/gen_schematic.py` の並び(P1〜P4 は 1 番が GND)。

| モジュールのピン | 信号 | つないだ先 | 目的 |
|---|---|---|---|
| P2-7 / P2-9 | USB D- / D+ | ESP32-C6 の GPIO12 / GPIO13 | RP2350 を USB ホストにして C6 と直結 |
| P2-15 / P2-14 | VBUS / GND | C6 ボードの 5V / GND | 2 枚とも C6 の UART の USB-C から給電 |
| P2-8 | GND | C6 の GND | データ線の横の GND |
| P2-10 / P2-6 | SWCLK / SWDIO | debugprobe(Pico)の GP2 / GP3 | SWD で書き込み・停止・メモリーの読み出し |
| P1-2 | GPIO0(UART0 TX) | debugprobe の GP5 | host_test のログ(**届かず、未解決**) |
| P2-4 → P2-16 | GPIO46(本体 5V 検出)→ 3V3 | 線でつなぐ | ファミコンが無くても「5V あり」にして画面転送のループを動かす |
| P4-15 | GPIO44(音の PWM) | 1kΩ → 10µF → イヤホン(根元は P4-1 GND) | PC の音を耳で確かめる |

### 4.2 作りの全体

| 項目 | 内容 |
|---|---|
| クロック | 250MHz(コア電圧 1.20V に上げてから) |
| コア 1 | バスの応答だけ。割り込み無しの 1 本のループを SRAM で動かす(`__not_in_flash_func`)。モードごとに `bus_loop` / `nsf_bus_loop` / `remote_bus_loop` |
| コア 0 | 起動、ROM の読み込み、USB(シリアル・画面転送・音)、本体の電源の見張り、メニューで選ばれた番号の見張り |
| PIO0 SM0 | `cpu_m2.pio`(GPIO 0〜31 の窓)。CPU の全サイクル |
| PIO1 SM0 | `ppu_chr.pio`(GPIO 16〜47 の窓)。PPU の /RD |
| PIO2 SM0 | `mirror.pio`(GPIO43)。PPU A10 / A11 を CIRAM A10 へ写す |
| DMA | 音(PWM へ 32kHz で流す)に 1 チャンネルと DMA タイマー 1 つ |
| SRAM の主な使い道 | ROM 384KB(PRG の後ろに CHR)、CHR-RAM 8KB、WRAM 8KB、NSF ドライバー 4KB、音のリング 16KB |
| 読み出しの作り | 8KB(PRG)/ 1KB(CHR)ごとのポインターの表を引くだけ。マッパーの計算は書き込みの時だけする |

### 4.3 起動の流れ

1. バスのピン(GPIO 0〜46、LED の 39 を除く)を全部入力・プル無しにする(RP2350 のエラッタ E9 のため、バスにプルダウンを使わない)。
2. コア電圧を 1.20V にして 250MHz にする。USB を始める(magicon はデバイス + USB シリアル、magicon_wifi はホスト)。
3. フラッシュの ROM 置き場を読む(`FCMG` = 1 本、`FCLB` = ライブラリ)。ライブラリなら、ウォッチドッグのメモ(scratch[0])にメニューで選んだ番号が残っていればその ROM、無ければメニューを組み立てる。1 本だけのライブラリはそのまま読む。
4. ROM を SRAM に写す(本体がリセットを解く前にバスへ出られるよう、5V を待つ前に済ませる)。駄目なら試験画面にする。
5. 本体の 5V(GPIO46)が来るまで待つ(LED を点滅、USB シリアルに `waiting for Famicom 5V`)。
6. PIO を設定し、コア 1 でバスの応答を始める(`cart_start`)。
7. コア 0 はモードごとのループへ。画面転送なら音を始めてから画面転送のループ。

### 4.4 CPU バスの応答

| 項目 | 内容 |
|---|---|
| 起こし方 | M2 で起きて全サイクルを拾う(`cpu_m2.pio`)。M2 が上がって 80ns 後にアドレス・R/W・/ROMSEL を読む |
| 読み出し | $8000-$FFFF(/ROMSEL = Low)は PRG、$6000-$7FFF は WRAM(マッパー 87 / 184 以外)。それ以外は出さない |
| 書き込み | PIO は M2 が下がる所でデータをもう一度読んで 2 回目を送る。コア 1 がマッパー・WRAM・PPU レジスターの横読みへ振り分ける |
| 出す時 | D0〜D7 を出すのは読み出しサイクルの間だけ(3.10 の決まり) |
| 数えるもの | CPU サイクル(約 179 万/秒)・PPU 読み出し・書き込みの回数(USB シリアルに 1 秒ごと) |

### 4.5 PPU バスの応答

| 項目 | 内容 |
|---|---|
| アドレス | /RD が High の間 AD0〜AD7 を読み続け、/RD が下がった時に最後に読んだ値を下位 8 ビットとする。上位は A8〜A12 |
| 出す時 | /RD = Low かつ A13 = Low(パターンテーブル)の時だけ。ネームテーブルは本体の VRAM が出す |
| CHR-RAM | PPU の書き込みではアドレスが読めないので、CPU の $2006 / $2007 への書き込みを横から読んで同じ所へ書く。$2000 の +1 / +32、$2002 の読み出し・$2005 で切り替わる「2 回目か」も真似る |
| MMC3 の IRQ | PPU A12 の立ち上がりを数え(A12 が Low の読み出しが 8 回続いた後)、GPIO45 → Q1 で /IRQ を出す |
| ミラーリング | PIO2 が PPU A10 / A11 を CIRAM A10(GPIO43)へ写す。水平・垂直・1 画面。JP1 を閉じた時だけ効く |
| **未検証** | /RD が下がってからデータを出すまでに間に合うか(chr_test と TP1・TP2 で測る)。駄目でも画面転送・NSF・CHR-RAM のゲームには響かない |

### 4.6 マッパー

PRG + CHR の合計 384KB まで(SMB3 の 256K + 128K が入る)。`tools/nes_pack.py` の表から作った。

| 番号 | マッパー | 特徴 |
|---|---|---|
| 0 | NROM | バンク切り替え無し |
| 1 | MMC1 | CHR-RAM も可。ミラーリング切り替え(JP1) |
| 2 | UxROM | CHR-RAM |
| 3 | CNROM | CHR 8KB 切り替え |
| 4 | MMC3 | スキャンライン割り込み(/IRQ)。ミラーリング切り替え(JP1) |
| 7 | AxROM | 1 画面ミラー(JP1) |
| 87 | Jaleco J87 | $6000-$7FFF の書き込みで CHR 切り替え |
| 184 | Sunsoft-1 | $6000-$7FFF の書き込みで CHR 4KB × 2 |

- WRAM($6000-$7FFF)8KB は電源を切ると消える(バッテリーのセーブはまだ)。
- 対応していない ROM は `nes_pack.py` がその場で止める(ライブラリなら飛ばす)。

### 4.7 NSF プレイヤー

| 項目 | 内容 |
|---|---|
| 置き場 | 曲のデータ = $8000-$FFFF(4KB × 8、$5FF8-$5FFF でバンク切り替え、384KB まで)。ドライバー = $5000-$5FFF(SRAM、本体側に何も無い所) |
| ベクター | $FFFA-$FFFF の読み出しだけ、ドライバーの番地を返す |
| 曲を始める時 | APU を黙らせ、本体 RAM と $6000-$7FFF を 0 にし、バンクを初期値に戻して INIT を呼ぶ(NSF の決まり) |
| 再生 | VBlank の NMI(約 60.1Hz)ごとに PLAY。再生間隔が標準と違う NSF はテンポが変わる |
| 操作 | ←→ = 前 / 次の曲、A = 最初から、START = 一時停止 |
| 画面 | ロゴ・曲名・作者・著作・曲番号。フォントは Consolas Bold 9pt から作った(`gen_nsf_driver.py`) |
| 変数 | $5F80-(NSF がゼロページを自由に使うため) |
| 未対応 | 拡張音源(VRC6・FDS・N163 など)、load が $8000 より下のバンク無し NSF、FDS 用の $6000-$DFFF を RAM にする NSF |

ドライバーの番地(`nsf_driver.h` から):

| 名前 | 値 | 意味 |
|---|---|---|
| `NSFD_BASE` | 0x5000 | ドライバーの先頭($5000-$5FFF はカセットの SRAM) |
| `NSFD_NT` | 0x0800 | 画面の土台(ドライバーの先頭から) |
| `NSFD_PARAM` | 0x0F00 | ファームが書く値: 曲数・最初の曲・バンクの初期値(先頭から) |
| `NSFD_RESET` | 0x5000 | リセットベクターが指す番地 |
| `NSFD_NMI` | 0x519A | NMI(PLAY を呼び、パッドを読む) |
| `NSFD_IRQ` | 0x5288 | IRQ(何もしない) |
| `NSFD_INIT_OPERAND` | 0x028A | INIT への JMP の番地の置き場(ファームが書く) |
| `NSFD_PLAY_OPERAND` | 0x028D | PLAY への JMP の番地の置き場 |

### 4.8 画面転送(リモートデスクトップ)モード

| 項目 | 内容 |
|---|---|
| 絵 | 256 x 240 ドット、2 ビット(4 色)。16 x 16 ドットごとに 4 組のパレットから選ぶ(背景の 1 色は共通) |
| しくみ | ネームテーブルに「(行 % 8) * 32 + 列」のタイルを並べておき、PPU が読みに来たタイル番号と行の中の y から画面の位置を割り出して、その 8 ドットを返す。8 行ごとの組は、タイル行が 7 → 0 になる回数で数える |
| 2 枚持ち | 絵と付随(パレット 32・属性 64・OAM 256)を表と裏で 2 組。1 枚届いたら、画面の最後(行 29 → 0)で入れ替える。表示待ちがある間は次を読まない(PC 側がそこで待つ) |
| 置き場 | 絵は ROM の SRAM(`rom[]`)の先頭を使う |
| カーソル | スプライト 4 タイル(16 x 16、パターンテーブル $1000)。PC が位置と表示の有無を送る |
| 6502 の仕事 | VBlank ごとに OAM DMA、パレット 32 と属性 64 を PPU へ、v を $2000 に戻す。1コンとキーボード(9 行 x 2 列、1 列ごとに 500µs 待つ)を読んで $5F00- に書く |
| レジスター | $2000 = $88(NMI 有効、背景 $0000、スプライト $1000)、$2001 = $1E |

6502 側の番地(`remote_driver.h` から):

| 名前 | 値 | 意味 |
|---|---|---|
| `RD_PAL` | 0x5D00 | パレット 32 バイト(VBlank ごとに 6502 が PPU へ写す) |
| `RD_ATTR` | 0x5D20 | 属性テーブル 64 バイト |
| `RD_OAM` | 0x5E00 | スプライト(カーソル)256 バイト。OAM DMA の元 |
| `RD_IO` | 0x5F00 | 6502 が書く入力: +0 パッド、+1〜+9 キーボード、+15 フレームの数 |

### 4.9 PC の音

| 項目 | 内容 |
|---|---|
| 出口 | GPIO44 の PWM → R9 1kΩ・C3(RC 約 15.9kHz)→ VR1 → R8 47kΩ → カセット端子 46 番(本体の音声に混ぜる)。J2(3.5mm)にも出る |
| PWM | 10 ビット(0〜1023、無音 = 512)、250MHz / 1024 = 約 244kHz |
| 流し方 | 8192 サンプル(256ms)のリング(16KB 境界)を、DMA が「終わり無し」+ 読み出しリングで比較値へ流し続ける。間隔は DMA タイマー(250MHz × 4 / 31250 = 32kHz) |
| 溜め方 | 届いた音は、鳴らしている所の 100ms 先に置く。150ms 以上溜まったら捨てる。鳴らし終えた所は無音で埋める(途切れても古い音を繰り返さない) |
| 形式 | 32kHz モノラル。16 ビット PCM / 8 ビット PCM / IMA ADPCM(4 ビット、パケットごとに最初の値と段を載せる)(7.4) |
| 使う時 | 画面転送モードの時だけ |

### 4.10 ゲーム選択メニュー

| 項目 | 内容 |
|---|---|
| 形 | NROM(PRG 32KB + CHR 8KB)。ファームが起動時にその場で組み立てる(`cart_load_menu`)。プログラムは `gen_menu_driver.py`、フォントとロゴは NSF プレイヤーの CHR |

### 4.11 本体の電源の見張り

- ゲーム・NSF・メニュー・画面転送のどのループでも、コア 0 が GPIO46(本体 5V)を見ている。
- 50ms 続けて Low なら scratch[0] を 0 にしてウォッチドッグで再起動する。USB から電源をもらっている時も、本体の電源を入れ直せばメニューに戻る。
- 再起動した後は 4.3 のとおり、5V が来るまでバスに出さない。

### 4.12 USB

| 項目 | magicon(デバイス) | magicon_wifi(ホスト) |
|---|---|---|
| TinyUSB | pico-sdk 付属 0.18 | 0.21.0(`C:\Users\Yugo\pico\tinyusb-0.21.0`) |
| 相手 | PC(USB シリアル = CDC) | J6 の ESP32-C6(USB Serial/JTAG = CDC ACM) |
| USB シリアル(printf) | あり | 無し |
| picotool の自動書き込み | あり(`load_rom.ps1` がそのまま使える) | 無し(BOOTSEL + RESET) |
| 画面転送の読み書き | `stdio_get_until` / `stdio_put_string` | `tuh_cdc_read` / `tuh_cdc_write`(入り切らない入力は捨てて次のフレームで送る) |

magicon_wifi の注意:

- pico-sdk の USB シリアル(`stdio_usb`)は、アプリが TinyUSB のホストを使うと丸ごと無効になる。そのため 1 つのファームウェアにまとめていない。
- TinyUSB 0.18 の RP2350 ホストは、バルク転送が「割り込み用の窓口」で 1ms に 64 バイト = 64KB/秒止まりで、返事に受け取ったデータが混ざって化けた。0.21 は EPX を順番に回す。
- 0.21 と pico-sdk 2.3.1 の組み合わせでは CDC の受信 FIFO の mutex が初期化されず止まったので、`CFG_TUSB_OS = OPT_OS_NONE`(と `tusb_time_millis_api`)にした。
- C6 を開く時は DTR だけ立てる(C6 の USB Serial/JTAG は RTS でリセットがかかる)。受信バッファ 4096 バイト。

| 取り込み | GDI の StretchBlt で 256 x 240 に縮めて取り込む。表示は「画面全体を縮小」(縦横比を保ち上下は黒)と「カーソルのまわりを等倍」 |
| 変換 | `nesframe.encode`(灰色 4 階調 / カラー)。カラーは前の画面の組から探す(チラつき防止) |
| 送信 | 送受信は別スレッド(`IoThread`)。画面を作る間に前の 1 枚を送る(順番にやると 15 枚/秒しか出なかった)。音のパケットは画面より先に送る |
| つなぎ先 | USB シリアル(COM、Win32 の CreateFile)か TCP(`--tcp`) |
| マウス | 十字キーで動かす(押し続けると 1 + 0.25 ずつ速く、12 まで。等倍表示では PC の 1 ドット単位)。A = 左クリック、B = 右クリック |
| 表示の切り替え | SELECT = 縮小 ⇔ 等倍、START = 等倍の時にカーソルを追うか止めるか |
| キーボード | SendInput でスキャンコード(JIS 配列)を送る。6.6 |
| 安全 | 入力が 0.5 秒届かない時と止めた時は、押しっぱなしのキーとボタンを離す |

オプション(`remote_pc.py` の `build_parser()` から):

| オプション | 内容 |
|---|---|
| `--port COMx` | COM ポートを指定する(既定: USB シリアルを探す) |
| `--color` | カラー(既定は灰色 4 階調。文字が読みやすい) |

### 6.3 画面の変換(nesframe.py)

| 項目 | 内容 |
|---|---|
| 灰色 | 全体で黒・濃い灰・薄い灰・白の 4 階調。文字がいちばん読みやすい |
| カラー | 背景の 1 色(いちばん多い色、上下の黒い帯は数えない)+ 3 色 x 4 組のパレット。16 x 16 ドットごとに 4 組のどれかを選ぶ |
| 組の決め方 | 組の区画でよく使われる色を候補に、3 つの枠を 1 つずつ入れ替えて誤差が減る時だけ採る |
| まだら対策 | 上下左右の区画と違う組には罰点(SMOOTH = 40)を足す。境目の段差 1.45 → 1.26(2026-09-27) |
| ディザ | Bayer 4 x 4 で 4 色の中間を点の混ぜ方で出す |
| 色の近さ | CIELAB の距離(RGB だと暗い緑が茶色に寄る)。表を前もって作って速くする |
| ファミコンの色 | agnes の表(PC の試験台の画面とドット単位で比べられるように) |

### 6.4 PC の音(pcaudio.py)

| 項目 | 内容 |
|---|---|
| 録り方 | WASAPI のループバックで既定の再生デバイスの音を録る(ctypes で COM を呼ぶ)。共有モード、溜め 200ms、20ms ごとに読む |
| 変換 | 各チャンネルを平均してモノラル、3 点の移動平均で高い音を少し落としてから、直線補間で 32kHz に |
| 形式 | `pcm16`(64KB/秒)/ `pcm8`(32KB/秒)/ `adpcm`(IMA、16KB/秒)。既定は USB 直結 `pcm16`、Wi-Fi `pcm8` |
| 聞き比べ(2026-09-27) | ADPCM は「サー」という雑音、16 ビットがいちばん綺麗、8 ビットは少し震えるが ADPCM より良い。「音より画面重視」で Wi-Fi は 8 ビット |
| 試験 | `python pcaudio.py --test`: ADPCM の往復 SN 比 32dB。1kHz を鳴らしてループバックで 1001Hz として録れる |

## 7. データと通信の形式

数はリトルエンディアン。

### 7.1 フラッシュの使い方

| 番地(フラッシュの先頭から) | 大きさ | 中身 |
|---|---:|---|
| 0x000000 | 8MB | ファームウェア(uf2 で書く。magicon は約 200KB) |
| 0x800000 | 8MB | ROM 置き場: 1 本(`FCMG`)かライブラリ(`FCLB`、127 本まで) |

- XIP の番地では 0x10800000。`load_rom.ps1` は picotool で `-o 0x10800000` に書く。
- 1 本の大きさは PRG + CHR で 384KB まで(RP2350 の SRAM に写して返すため)。ライブラリ全体は 8MB まで。
- ライブラリの項目は 64 バイト(題名 48 + 位置 4 + 長さ 4 + 合計 4 + 予備 4)、題名はメニューで 28 文字まで。

### 7.2 ROM 置き場: 1 本(FCMG)

| 位置 | 大きさ | 中身 |
|---|---:|---|
| 0 | 4 | `"FCMG"` |
| 4 | 4 | 中身の長さ |
| 8 | 4 | 中身のバイトの合計(32 ビット) |
| 12 | 4 | 予備 |
| 16 | 長さ | .nes / .nsf をそのまま、または `"FCRD"`(画面転送モード) |

### 7.3 ROM 置き場: ライブラリ(FCLB)

| 位置 | 大きさ | 中身 |
|---|---:|---|
| 0 | 4 | `"FCLB"` |
| 4 | 4 | 項目の数(1〜127) |
| 8 | 4 | 全体の長さ |
| 12 | 4 | 予備 |
| 16 + 64 × i | 48 | 題名(ASCII、0 で終わる) |
| +48 | 4 | 中身の位置(置き場の先頭から) |
| +52 | 4 | 中身の長さ |
| +56 | 4 | 中身のバイトの合計 |
| +60 | 4 | 予備 |
| 目次の後(16 バイト境界) | — | 中身を並べる(1 本の時と同じ .nes / .nsf / `"FCRD"`、16 バイト境界) |

### 7.4 画面転送の通信

USB でも TCP でも同じ並び。カセットは `FCFR` / `FCAU` を 1 バイトずつ探すので、途中から読み始めても合う。

| パケット | 向き | 並び | 大きさ |
|---|---|---|---:|
| 画面 | PC → カセット | `"FCFR"` + 絵 15360 + パレット 32 + 属性 64 + カーソルの x・y・表示(3) | 15463 |
| 音 | PC → カセット | `"FCAU"` + 形式 1 + サンプル数 2(1〜1024)+ 中身 | 7 + 中身 |
| 入力 | カセット → PC | `"FCIN"` + 16(下の表)。6502 のフレームの数が変わるたび(約 60 回/秒) | 20 |

| 音の形式 | 値 | 中身 |
|---|---:|---|
| 16 ビット PCM | 0 | サンプル × 2 バイト(符号付き) |
| IMA ADPCM | 1 | 最初の値 2 + 段 1 + 4 ビット × サンプル数(下位の 4 ビットが先) |
| 8 ビット PCM | 2 | サンプル × 1 バイト(符号付き) |

| FCIN の位置 | 中身 |
|---|---|
| 0 | パッド(bit7 = A、6 = B、5 = SELECT、4 = START、3 = ↑、2 = ↓、1 = ←、0 = →) |
| 1〜9 | キーボード 9 行(下位 4 ビット = 列 0、上位 4 ビット = 列 1、押すと 0) |
| 10〜14 | 予備(試験用ファームでは受け取った枚数などを入れる) |
| 15 | 6502 のフレームの数 |

### 7.5 画面のデータの並び

| もの | 並び |
|---|---|
| 絵 | タイル行 r(0〜29)、行の中の y(0〜7)、列 c(0〜31)、面 p(0/1)の 1 バイト = `fb[((r × 8 + y) × 32 + c) × 2 + p]`。1 バイト = 横 8 ドットの 1 面 |
| パレット | 背景 16 + スプライト 16(ファミコンの色番号) |
| 属性 | ファミコンの属性テーブル 64 バイトそのまま(16 x 16 ドットごとの組) |
| カーソル | x(0〜255)、y(0〜239)、表示(0/1) |
