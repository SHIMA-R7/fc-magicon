# 4fps動画の更新方式を変更する比較版

前の4fps試行でも画質が厳しいとの実機報告。更新頻度だけを減らしても、CHRを先に置換し、CIRAMのNTを8VBlankかけて書き換える旧処理では新旧フレームが混在する。

比較版は背景CHRの$0000/$1000を2面に分け、次のフレームのCHRを非表示側へコピーする。実機のCIRAMも垂直ミラーの$2000/$2400を表示/作業面として交互に使う。次のNT/属性1024バイトを128バイトずつ8VBlankで作り、最後のVBlankでパレットを更新、$2000のNT選択・背景パターン選択を同時に切り替える。

6502が$5F10でpendingと次のbankを読み、表示切替後に$5F11へbankを書いてACKする。それまで次のPCフレームを受け付けず、作業データを固定する。タイル変換のキャッシュが同じパターンを省略しても、ステージ全4096エントリを非表示側へコピーするため、2面の差が残らない。

検査:

- 実際の比較用cart.cをホストでコンパイルし、6フレームの交互更新で表示中CHRが変わらないこと、ステージ全体コピー、メタデータを正しいACKまで保つことを確認。
- 生成した6502をpy65で実行。6フレームで旧NTと旧パレットを最後のVBlankまで維持、NT/CHR選択の一致、ACK順序を確認。NMI最大1675CPUサイクルでNTSC VBlank約2273サイクル以内。
- 4fps・120枚を、場面ごとに独立したパレット探索（背景候補4色、8反復、ディザなし、平滑化罰点0）で再変換。各フレームを256タイル以内へ近似し、実際のremote_full.h変換後のRGBが事前変換画像と一致することを全120枚で確認。

PIO音声の成功版を維持し、再生時に `--audio-gain 20` を使う。元素材のピーク1249を24980へ増幅、クリップ0。映像レート4fps、音声32kHzモノラル。

## 実機録画による確認

その後ユーザーの「転送どうぞ」を受け、独立パレットの4fps素材・音声ゲイン20で30秒再生。ホスト提供120枚、最終チャンク書込120枚、4.0枚/秒。音声受信/受理は一致し、再生中の先行量約2544〜3776サンプル。

ユーザーが `ブルアカ7thPV-4fps-1.mp4` を作業フォルダへ保存し「だいぶ良くなった」と報告。49.53秒、1920×1080、約60fpsのカメラ録画を確認した。4秒刻みの場面抜粋と録画20〜22秒の8fps抜粋で、従来の大きな新旧タイル混在に比べて改善を視覚確認。実機での全ドット一致や全フレームの無破綻を測定したものではない。

残る目立つ問題は、色変換/タイル近似による平坦な色面・局所的なブロック、独立パレット探索に伴う青/灰などのフレーム間変動、4fps自体の動きの粗さ。次の画質改善はパレットの時間方向安定化を、場面ごとの色選択の自由を残して行う方向が有望。

録画はローカル資料で公開対象に含めない。現在Flash上の比較版を実機で改善確認できた基準として保存する。
