# 指定YouTube動画の冒頭30秒・転送表示検証

対象：[【ブルアカ】7th PV](https://www.youtube.com/watch?v=U6Wlb18KLrI)。ユーザー指定の0～30秒だけを公開ストリームから取得し、実映像を入力にした。ブラウザー操作ツールは初期化エラーで利用できず、ブラウザー再生の画面収録ではない。

動画900枚を256×240・30fpsにそろえ、実際の `nesframe.encode` のカラー変換（前のパレットを引き継ぎ、初回4・以降2反復）に通した。変換時間は平均26.86ms、95パーセンタイル31.27ms、最大43.83ms。900枚中31枚が33.33msを超えた。キャプチャ・実通信時間は含めない。

RetroArch用Nestopiaの検証コアと既存6502ドライバーで、各画像を2表示フレームずつ描画。1,800表示フレームすべてで変換後RGBとの画素差は0。検証コアはエミュレーターの走査線情報を使い、タイル圧縮なしの全面フレームバッファを読み出す。実機のPIOや位置検出、通信待ち、現在の実機用256タイル圧縮は再現していない。したがって、これは30fpsに組み立てた理想条件の表示結果であり、実機転送の録画ではない。

音声は元の音を32kHzモノラルにし、実際のPC側PCM16パケット生成、C側復号、`audio.c` と同じ10bit PWM量子化を通した。938パケット・959,776サンプル（約29.993秒）。プレビューMP4ではAACで格納。アナログ出音、実通信の途切れ、実機の100ms音声バッファ遅延は含めない。

成果物は `firmware/sim/retroarch-remote-20261013/youtube-U6Wlb18KLrI/`：

- `transferred-30s.mp4`：転送後だけのカラー表示、30秒・30fps。
- `comparison-30s.mp4`：左が元映像を256×240に縮小したもの、右がNestopia表示。
- `frame-05s.png`、`frame-10s.png`、`frame-20s.png`：目視確認用。
- `conversion-results.json`、`validation-results.json`、`nestopia/stream-results.json`：測定・一致検証。

両MP4は全体の復号成功を確認。実機には書き込んでいない。
