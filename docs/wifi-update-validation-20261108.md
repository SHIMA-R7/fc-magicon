# 無線更新・本体DAC再生の実機検証（2026-11-08）

## 試験構成と結果

ツインファミコンからカセットとESP32-C6へ給電し、PCとのカセット/C6 USB接続を外した構成で試験した。PCへ接続したDP100で電源を操作し、映像・音声をキャプチャーした。

Wi-Fi→C6→SWDで更新対応版を導入・照合。その後はWi-Fi→C6→USBで全編メディアとプレーヤーを更新し、電源再投入により単独再生した。RP2350Bのフラッシュに映像・ADPCM音声を保存し、6502プログラムがFC本体の7ビットDAC `$4011` に224 CPUサイクル間隔（NTSCで約7.99 kHz）で出力する。全編536コマ、8fps、約67秒。

| 項目 | OLEDなし | OLED＋ユーザー追加パスコン |
|---|---:|---:|
| メディア転送・照合（9,389,980バイト） | 83.94秒 | 81.89秒 |
| プレーヤー更新・照合（78,212バイト） | 1.50秒 | 1.47秒 |
| 全編録画 | 1回 | 2回 |
| 再生時のDP100出力 | 7.591〜7.599V | 7.589〜7.598V |
| 周期的測定での最大電流 | 0.771A | 0.687A／0.681A |
| 録音バッファオーバーフロー | 0 | 0／0 |

メディアCRC32は `8ec2b219`、プレーヤーCRC32は `47e197b2`。両構成で同じデータ・ファームを使用。DP100設定は7.6V、電流上限1.25A。終了時に出力OFF・0V・0Aを確認した。

## OLED接続時の起動

追加パスコンの種類・容量・配置は今回の記録では確認していない。

最初の起動では45秒間Wi-Fiへ接続できず、書き込みを行わずOFFにした。その後の全編再生時にはWi-Fi/SWDへ到達し、続く起動では約3.3秒で接続して無線更新できた。OFFを3秒挟む追加起動試験3回では、それぞれ2.594秒・2.562秒・3.812秒でWi-FiとSWDの両ポートへ接続した。その後の全編再生も完了した。

成功した起動だけを数えて完全解決とは扱わない。パスコン追加とOLED取り外しの効果を断定できる対照試験ではなく、RP/C6の3.3V電源波形も測定していない。電流値は低周期サンプリングで、突入電流の上限ではない。

## 映像と音声

冒頭ロゴから本編・終盤までの進行を録画で確認。全536コマを実機読み戻しして無欠損を保証したものではない。色数・タイル単位の制約、アナログ由来のノイズは残る。

入力ADPCMから実際のDAC値列を復元し、録音の5・15・25・35・45・55・60秒付近の各4秒窓と比較した。OLED＋パスコンの2回目は位相反転を含む相関の絶対値が約0.65〜0.92。終盤にも再生信号があり、途中から無音になる症状はこの2回では再現しなかった。前回と同じ区間の音量差は概ね0.1〜0.2dBで、大幅な音量・ノイズ改善を示す結果ではない。

録画は同時収録した実機音声を使用した。視聴用MP4には+18dBの音量調整、ピーク制限、映像と音声の収録開始位置合わせを実施し、原曲やエミュレーター音声への差し替えは行っていない。素材・録画・素材を含むバイナリーはリポジトリに収録しない。

## ソフトウェアと再現方法

Pico SDK 2.3.1、TinyUSB 0.21.0、ARM GCC 15.2.1を使用。実機版のCMake指定は次の通り（ローカルのSDK・ツール配置は環境に合わせる）。

```text
FC_STANDALONE_VIDEO_ONLY=ON
FC_TUSB021=ON
FC_PLAYER_COLD_BOOT=ON
FC_REMOTE_WIFI=ON
FC_REMOTE_DESKTOP=OFF
FC_PLAYER_FULL_TILES=ON
FC_FULL_TILES_MOVIE=ON
FC_PLAYER_NATIVE_PCM=ON
FC_PLAYER_NATIVE_RAM=ON
FC_PLAYER_DIRECT_BOOT=ON
FC_MEDIA_OFFSET=0x100000
FC_PLAYER_AUDIO_LOG=OFF
```

RAM常駐6502ドライバーは、py65で定周期DAC出力とVBlank中の更新を検査する。

```powershell
python firmware/tests/test_native_pcm_video_driver.py
python firmware/tests/test_native_pcm_video_driver.py --ram
```

[USB更新手順](c6-usb-update.md) ／ [SWD導入・復旧](c6-swd-programming.md)

## 公開前の再検査

公開対象のソースから、フルフレーム本体DACプレーヤー、Wi-Fiリモート版、従来USBリモート版の3構成をビルドして成功。無線更新の解析処理はWi-Fi構成でのみ有効になるようにした。

次の8コマンドが成功した。検査入力は合成データで、作品の音声・映像をリポジトリへ追加していない。

- `test_native_pcm_video_driver.py`：224サイクル間隔、35回の完全なVBlank更新。
- `test_native_pcm_video_driver.py --ram`：同じ間隔・更新条件をRAM常駐コードでも確認。
- `test_native_pcm_ring.py`：C実装の復号・間引き・折返し・EOF・アンダーラン。
- `test_full_tiles_driver.py`：パレットと属性の書込み順序、更新ACK。
- `test_full_tiles_pio.py`：384組の位置・ビットプレーン、DMA期限、バス解放。
- `test_fcpv_lz4.py`：C実装のLZ4、切詰め・境界検査。
- `test_adpcm_video.py`：C/Pythonの復号一致、形式互換性、不正ヘッダー拒否。
- `test_wifi_sender.py`：通常・分割送信と切断処理。
