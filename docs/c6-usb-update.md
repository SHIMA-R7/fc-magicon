# C6のUSB転送を使うRP2350ファーム・メディア更新

PC → Wi-Fi/TCP 5000 → ESP32-C6 → USB CDC → RP2350Bの経路で更新します。RP2350BはUSBホスト、C6はUSBデバイスです。カセットにPCのUSBを接続せず、FCからの給電だけで更新する動作を確認しました。

## 導入と更新

初回はBOOTSELまたは[SWD](c6-swd-programming.md)で更新対応ファームを導入します。USBホスト版をPCのUSBデータ線につないだまま実行しないでください。C6側GPIO12/13をRPのUSB D−/D＋へ、GNDを共通にします。

```powershell
# SDK生成のARM Secure版BIN。上限128 KiB。
python firmware/tools/update_via_c6.py firmware.bin --host fc-magicon.local

# 自分の素材から生成したFCPV。フラッシュの0x100000以降、最大15 MiB。
python firmware/tools/update_via_c6.py movie.fcpv --media --host fc-magicon.local
```

現在の受信版では、再生中・リモート受信中に更新要求を受けられます。全編メディアを書き終えてから、そのメディアに対応するプレーヤーを更新します。ファーム更新後は結果通知を返して待機するため、完了通知を受けてから外部電源をOFF→ONします。試験ではDP100で操作しました。FCからの給電だけでは、FCをOFFにするとC6とRPの電源も切れる点に注意してください。

旧版の更新機能はFC電源検出がLowの間だけ動作しました。この版は電源を維持できる別給電が必要で、FC給電だけの構成にはそのまま使えません。

## 検査と中断時の扱い

ファームは全データをRAMへ受信し、CRC32・サイズ・ベクターを検査してから更新します。カセットの出力を入力側へ解放し、PIO・DMA・もう一方のコアを停止して、RAM上のコードでフラッシュを書き換えます。書込み内容を照合し、古いXIPコードへ戻らず再起動します。更新先ファームにも更新機能が必要です。

メディアは4 KiB単位で消去・書込み・読み戻しを行い、最後に全体CRC32を照合します。範囲はファーム領域と分離していますが、途中で中断すると旧メディアは保持されません。メディア転送を最初からやり直してください。電源断や起動失敗で受信できなくなった場合はSWD/BOOTSELで復旧します。A/B領域や電源断に対する原子的更新は実装していません。

TCP 5000/5001は認証なしのローカル開発用です。信頼できるLAN内で使ってください。

## 確認結果

2026-11-08、全編メディア9,389,980バイトを81.89秒、プレーヤー78,212バイトを1.47秒で転送・照合しました。OLED接続・追加パスコンの構成で、全編映像とFC本体DAC音声を2回録画しました。初回のみWi-Fi接続に失敗し、その後の再起動3回は接続できました。詳細は[実機試験記録](wifi-update-validation-20261108.md)を参照してください。
