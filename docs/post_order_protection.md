# 発注済み rev0.2 の保護対策（2026-10-10）

基板は発注済み。元のガーバーを変更せず、ファームと後付けで対策する。
ファームは実装・ビルド確認済み。後付け回路は設計案で、現物の取り付け・電源波形・バス応答の検証は未実施。

検証結果: 4種類の最終UF2をビルド成功。実際のpower_guard.hを模擬レジスターへ組み込んだテストで、立ち下がり検出、起動中のLow、10µs待機を確認。PIO停止、全対象OE遮断、LED/PSRAM除外、メニュー復帰指定を確認した。模擬テストは電圧・実機の割り込み遅延を検証しない。

## 実装したファーム

対象は magicon / magicon_wifi / bus_test / chr_test。

- GPIO46の5V検出に立ち下がり割り込みを登録。検出後は外部GPIOのOEを強制Lowにし、PIO0/1/2を停止する。LED39とPSRAM47は触らない。
- CPU/PPUのデータ出力、CIRAM43、音声44、IRQ45を遮断する。PWM/DMAが残っていてもGPIOの出力許可で止める。
- 割り込み処理から戻らず、約50ms後にウォッチドッグで再起動。コア0のUSB受信・音声初期化・バス設定を再開しない。コア1がPIOへ書いてもGPIOのOE強制禁止は解除されない。
- 瞬間的な検出Lowも停止扱い。5Vが復帰しても、停止したままリセットする。ライブラリ選択情報を消してメニューへ戻す。
- 5V待ちは10µs間隔。100ms単位の待ちと検出直後のprintfを廃止。
- bus_test/chr_testのROM/CHR準備を電源待ちより前へ移動。
- FCが既にONならUSB初期化をバス応答開始後へ移動。USBのみの先行給電ではUSB初期化し、単体のpicotool書き込みを維持。
- magiconはmain開始からROM準備とバス応答開始までの時間を出力。boot ROMと電源立ち上がりは含まないため、27msとの比較にはオシロを使う。

割り込み応答には実行時間があり、電源電圧そのものを監視するハード保護の代わりではない。IOVDDが未給電のときの5V入力はファームでは保護できない。
250MHz用のコア電圧安定待ち10ms、ROMの整合性確認は残した。測定せずに削ると別の不安定さを増やすため。

## 保護回路が未実装の間の給電手順

1. FCもUSBもOFFの状態でカセットを挿す。通電中に抜き差ししない。
2. FPC-USBからモジュールを先に給電し、3.3Vを測定する。D1の向きとFC側5Vへの逆流が無いことも確認する。
3. 待機LEDの点滅を確認してからFCをON。
4. 終了はFCを先にOFF。その後USBを外す。

Wi-Fi版はUSBがホストになる。PCのUSBホストへ接続しない。C6のUART側USB-Cなど既存の給電構成を使い、Core2350B2のVBUSと3.3Vが先に立ち上がることを測定する。J6とFPCに同時にUSB機器を接続しない。
D1を短絡しない。既存モジュールの電源回路を確認せずに外部3.3Vを注入しない。

## 後付け案：ソケット間のバス遮断インターポーザー

既存P1～P4とCore2350B2の間に挟む。既存銅配線は切らず、モジュール側の信号を直通させないことで遮断回路を挿入する。
J4へ部品を並列接続するだけでは元の直結経路が残るため、保護にならない。

方式はSN74CB3Q3245を6個使う双方向バス遮断。GPIO0～46のうちLED39を除く46信号を遮断し、GPIO47は元通り。
方向信号は不要で、CPU/PPUの双方向データにも使用できる。GPIOの追加割り当ても不要。
これはレベル変換器ではない。ON中は5V信号も通すので、MCUのIOVDDが適正なときだけ接続する。
GPIO40～42は既存U2の3.3V出力を通し、ADC兼用GPIOへ5Vを入れない。

各スイッチはMCU側3.3Vで給電。100nFを各ICのVCC/GNDの直近へ置く。/OEは共通で10kΩにより3.3Vへプルアップし、既定状態を遮断とする。
共通/OEをNPNのコレクタでLowへ引く。NPNのエミッタはGND、ベースには4.7kΩ、ベース-GNDは100kΩを初期候補とする。
NPNのピン順は選んだ型番のデータシートで確認する。

接続を許可する条件は「モジュール3.3V正常 AND FC5V正常」。TPS3808G01を2個使い、open-drain /RESET出力を接続して10kΩで3.3Vへ引き上げる。その出力を上記ベース抵抗へ入れる。

| 監視 | SENSE上側抵抗 | 下側抵抗 | 公称しきい値 |
|---|---:|---:|---:|
| MCU 3.3V | 68.1kΩ | 10kΩ | 3.163V |
| FC 5V（D1より本体側） | 91kΩ | 10kΩ | 4.091V |

計算は0.405×(1+上側/下側)。抵抗は1%以下。TPS3808のVDDはMCU側3.3V、GND共通、MRは未使用として資料の指定通りに処理。
CTは各100pFを初期候補とする（公称約1.07ms。部品公差・配線容量・データシートの遅延範囲を確認する）。CT開放では約20ms待つため、起動時間を圧迫する。
SENSEのフィルター容量は停止応答を遅らせるので、値を実測前に固定しない。

元のR2/R3のGPIO46用分圧はそのまま。FC5V監視用の91k/10kは別に追加し、既存の分圧を変えない。
GPIO46のモジュール側には1MΩのGNDへの抵抗を追加し、スイッチ遮断時に電源検出入力が浮かないようにする。既存分圧への負荷と、遮断後の電圧降下時間を確認する。
監視対象はICの品番末尾、しきい値公差、最低VDD時の/RESET状態、NPNの遮断・飽和、監視IC停止時の入力定格まで含めて検証する。
この回路の低電圧区間や信号負荷は現物で未検証なので、製造・実装済みとは扱わない。

### 機械面と配線

- 接続は `protection_connections.csv`。列のsocket_pinは既存生成スクリプトから抽出する。上面/下面の視点を間違えない。
- ピンソケットを二重にすることで高さが増える。ケースとの干渉はCore2350B2の実物と照合する。
- まず小型変換基板で電源監視＋1個のバススイッチを単体検証する。その後6個へ展開する。
- 高速信号の長いUEW引き回しは避け、GND面のある小基板にまとめる。特にPPU AD0～7の負荷が増えると下位アドレス読取りのタイミングが変わる。
- CIRAM43の遮断を含める。音声44・IRQ45の外部回路側には既存R9・R4/R5が残る。
- P2のGND/VBUS/3.3V/SWD/RUN/USB/BOOTSELは直通。ADC_VREF/3V3_EN/PSRAM_CSは元の基板側で未接続なので新たに接続しない。

## 小改造の候補

- D1をショットキーに替える場合は耐圧・電流・逆漏れを選定し、電圧降下改善だけの対策として扱う。D1短絡はしない。
- 既存U2の/OE常時GNDを止め、監視回路の共通/OEへ接続する案もある。DIPソケットの19番を浮かせて接続すれば銅配線を切らずに済む。U2側3.3Vへのプルアップを付け、他のピンと短絡しないよう固定する。
- C1の増量は電源波形を見てから。突入電流と立ち上がり遅延も測る。大容量化だけでは入力保護にならない。
- 直列抵抗だけを5V保護と呼ばない。リンギング対策に使う場合は信号ごとに測定して値を選ぶ。
- 本体リセットの延長は、カセットから信号を取り出せないため本体改造が必要。対象本体のRESET信号を実測・導通確認するまで接続先を指定しない。カセットのSW2はRP2350のRUNであり本体RESETではない。

## 到着後の検証

| 試験 | 観測するもの | 合格条件 |
|---|---|---|
| USBのみ | MCU3.3V、FC側5V、データ線 | FC側へ給電せず、外部出力はHi-Z |
| USB先行→FC ON | FC5V、MCU3.3V、M2、/ROMSEL、データ | 5V入力が来る前にIOVDDが安定、最初のROMアクセスへ応答 |
| FC OFF／USB継続 | GPIO46、CPU/PPUデータ、CIRAM43 | 検出Low後に出力解放、50ms程度後に再起動して待機 |
| USB受信中／音声中にFC OFF | 同上＋音声44 | USB処理のタイムアウトを待たず出力解放 |
| 保護追加基板単体 | 電源0Vで外部に5Vを印加 | MCU側へ5Vを通さず、部品定格内。FC本体は接続しない |
| 保護追加基板の起動・停止 | 3.3V、5V、/OE、MCU側信号 | 電源有効区間だけ接続。OFFで遮断 |
| bus_test→chr_test→magicon | TP1～TP5、表示・音声 | 最小構成から順に確認。追加回路の有無で遅延・波形を比較 |

電源投入からmainまでの時間はログだけでは測れない。まず手持ちHVC-CPU-07で測り、ツインの27msをそのまま適用しない。
無給電5Vの試験はRP2350へ直接行わず、遮断回路単体で行う。
