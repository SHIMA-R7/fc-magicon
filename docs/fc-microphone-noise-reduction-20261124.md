# 2コンマイク録音の定常ノイズ低減

2026-11-24、ユーザーが声の明瞭さと2コンAでの開始・停止を実機確認。
その後の正常終了録音4本から、定常成分を測定した。音声原本は公開しない。

## 分析

- 約5.056 kHzに強い定常成分。約745 Hz、1.437 kHz、2.182 kHzなどにも細い成分が継続している。
- 声が小さい2本の録音に共通するピークを照合し、13本のノッチを設定した。
- 周波数は `firmware/tools/mic_noise_profile.json` に保存。帯域幅は4.5 kHz未満で10 Hz、それ以上で16 Hz。
- 無信号の別診断ではなく、録音と同じ16 ksample/s・UART 460800 baudで動かしたデータを使った。
- ノイズの電気的発生源は未確定。この結果だけで電源・配線・ADC・USB等のどれが原因かは断定しない。

## 処理と評価

| 処理 | 声の小さい区間のRMS低下（4本） | 用途 |
|---|---:|---|
| 固定の狭帯域ノッチ13本 | 6.05～6.37 dB | 録音ソフトの標準処理 |
| ノッチ＋雑音プロファイルによるスペクトル抑制 | 13.96～15.53 dB | 聴き比べ用、標準処理には未採用 |

各録音で、元音声の4096サンプル窓（1024サンプル間隔）のうちRMSが下位20%の窓を選び、
処理前後で同じ位置を比較した。自動音量正規化は行っていない。
これは声の小さい区間の総レベル差であり、純粋なS/N比や主観的な聞きやすさの改善量ではない。

最後の約6.9秒の録音では、声の小さい区間が-33.04 dBFSからノッチで-39.30 dBFS、
強めの処理で-48.07 dBFSへ低下。元音声の大きい区間（上位20%）の総レベル変化はノッチで-0.21 dB。
小さいレベル差だけで声質が完全に保たれたとは判断せず、比較音声で確認する。

## 録音ソフトへの反映

`fc_mic_denoise.py` は標準ライブラリだけで動作する状態保持型ノッチフィルター。
`record_fc_mic.py` は元のWAVと並行して `-clean.wav` を保存し、ADC原本も保持する。
フィルター状態は録音ごとにリセットし、パケット境界では継続する。
切断時は処理版も `.partial-clean.wav` として残す。

16 kHzで200 Hzと実測ノイズ周波数を混ぜた信号による検査では、
200 Hzの振幅を97%以上保ち、5.056 kHzの成分を34 dB以上抑制。
全体を一括処理した場合と256サンプルずつ処理した場合の結果が一致した。
このPCでの実測処理時間は音声1秒あたり約0.077秒。元音声・処理版のWAVサンプル数一致も確認した。

## 限界

- 波形が振り切れた部分の情報は復元しない。
- 狭帯域処理でも、その周波数にある声の成分は一緒に抑える。
- 強めの処理は声質変化の確認が必要。現時点では比較用ファイルとしてのみ作成した。
- 個体やサンプリング条件、UART速度等を変えると周波数が変わる可能性があるため再測定する。

比較音声と測定値はユーザーのドキュメント内 `FCマイク録音/ノイズ除去比較/` に保存。
比較ファイルは前半が原音、0.5秒の間隔の後に同じ箇所の処理音。音量は揃え直していない。
