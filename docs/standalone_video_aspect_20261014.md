# 単独再生映像の4:3表示補正

ファミコンの256×240の有効画面全体を4:3で表示する前提で、元動画16:9の縦横比を保つ。

| 項目 | 以前 | 補正版 |
|---|---:|---:|
| 画面のデータ寸法 | 256×240 | 256×240 |
| 映像部分のデータ寸法 | 256×144 | 256×180 |
| 上下の黒帯 | 各48行 | 各30行 |
| 全画面を640×480に表示した場合の映像部分 | 640×288（20:9） | 640×360（16:9） |

表示時の横方向の拡大率は縦方向の1.25倍。保存時に映像を縦180行に変換しておくと、表示時に元の比率になる。元動画から再変換し、以前の減色済み画像を引き伸ばしてはいない。

比較動画も左右とも640×480の表示領域に変更。左は元動画640×360と上下60ピクセルの黒帯、右は保存したCHR・ネームテーブル・パレットを復元し640×480に表示する。上の説明欄を含む動画全体は1280×544。

## 再生成

1. `firmware/sim/prepare_standalone_full.py --display-4x3` で全99秒・8fpsを変換する。別の `full-8fps-4x3` キャッシュを使用する。
2. `firmware/tools/pack_flash_video.py` で `pv-full-99s-8fps-4x3.fcpv` を作成する。
3. `firmware/tests/test_standalone_video.py <media> --cold` で実際のC実装と6502ドライバを検査する。
4. `firmware/tools/make_standalone_uf2.py` で既存のcold bootファームウェアと結合する。USB・実機へのアクセスは行わない。
5. `firmware/tools/render_standalone_comparison.py` で比較動画を作成する。

短い実機確認用の30秒・4fps版は、補正版8fpsデータの先頭30秒から1枚おきに取り出す。音声は先頭30秒を使用する。

映像レコードの長さ、フレーム数、音声形式は変更しないため、全編データの容量は7,248,448バイトのまま。起動処理や再生ファームウェア自体の変更は不要。

4:3表示を仮定したPC上の再構成であり、実機の表示範囲・オーバースキャンによる差は未確認。実機への書き込みは行っていない。

- 30秒書き込み用：`firmware/out-standalone-video/pv-30s-4fps-4x3-cold-20261014.uf2`

全792フレームの保存データからの復元一致、C実装と6502ドライバによる全フレームの7-VBlank切り替え、起動待機からの引き継ぎ、音声リングと200ms補充期限の検査が通過。最大NMI処理1779 CPUサイクル。結合UF2からも映像・音声領域を再構成して一致を確認した。30秒版120フレームも同じ検査が通過。

音声付き比較動画を復号して検査。30秒版の復号音声は30.016秒、ピーク26132、RMS5309.68（符号付き16bit換算）で、無音ではない。4:3表示の比較静止画も目視確認した。実機での音量・同期・起動成功を確認したという意味ではない。
