# FC側のネームテーブル読み戻し診断

問題場面の静止画（元PV22.75秒）を一度だけ表示し、FCの6502がPPU $2007から表示側ネームテーブル1024バイトを読み戻す。32バイトずつ32回のVBlankで検査し、毎回の最初のダミー読みを捨てる。期待値はMCUに保存されている$6000〜$63FFの転送元。属性64バイトも含む。

検査中はMCUが次のフレームを転送しない。音声PIO/DMAも起動しない。この診断は静止状態の検査であり、音声や連続フレーム転送による負荷の再現ではない。

## 結果の表示

- 緑一色：読み戻し1024バイトが一致。基板LEDは1回点滅を繰り返す。
- 赤一色：1バイト以上の不一致。基板LEDは2回点滅を繰り返す。
- 判定色に変わらない：画面内容とLED点滅回数を確認する。MCUが診断完了を10秒待っても受け取れない場合、故障コード6の点滅。

結果コードは$5F20（0=未開始、1=検査中、2=一致、3=不一致）。$5F21/$5F22に不一致数の下位/上位バイト。画面全体を判定色にするため、検査完了後に全パレットを同色に書き換える。判定後の緑/赤画面自体は異常表示ではない。

一致はこの静止条件でのNTの一致を意味する。CHR・パレットの読み戻し、連続転送中の書き込み、電気的なタイミング余裕まで合格とするものではない。不一致にもCPU期待値読み出し・PPU書き込み・読み戻し等の複数の原因があり、CIRAM単体不良と断定しない。

## 検証とビルド

実Cと6502命令を用い、PPU $2007の遅延読み出しバッファをモデル化した。垂直/水平ミラーの一致ケースが成功し、表示側NTの全1024バイトを意図的に変更したケースで1024不一致・赤を検出。転送と検査を通じた最大NMIは1789 CPUサイクル、モデル上の2273サイクル枠内。

`gen_video_driver.py baseline/readback_driver.h --readback` で診断ROMを生成。通常のROMとは別ファイル・別コンパイルスイッチを使う。`build.ps1 -ColdBoot -Readback` で別ASCII作業フォルダと別ファーム名を使う。従来の改善版・比較版UF2は保持している。
