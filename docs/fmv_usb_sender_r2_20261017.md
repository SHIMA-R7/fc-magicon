# FMV USBリモートデスクトップ送信アプリ r2.3

ZIPをすべて展開して `FC-MAGICON-USB/FC-MAGICON-USB.exe` を開く。Python不要。EXEだけを取り出さない。配布用コピー：作業フォルダ `output/FC-MAGICON-USB-Win11-20261017-r2.zip`。

基板をFMVへUSB接続し、FCをON。「再検索」→基板のCOMポート→「転送開始」。このファームはFC側のドライバー起動後にUSBシリアルを有効にする。既定はカラー・8fps上限・全画面・PCM8音声。FMVでの前版実測ログは約3.8～4.5fpsで、8fpsを保証するものではない。

## 操作

- 十字キー：マウス移動。A：左クリック、B：右クリック。
- SELECT：通常（画面全体）→少しズーム（PC上の512×480範囲）→ズーム（従来の256×240範囲）→通常。
- START：少しズーム／ズームの追随ON・OFF。小さい画面では取り込み範囲を画面内に制限する。
- 「ゲーム向けマウス（相対移動）」：Windowsへ相対移動イベントを送る。従来の位置指定と切り替えて比較する。ブルーアーカイブでの有効性は実機確認待ちで、ゲーム側の特殊な入力処理や権限問題を解決すると保証しない。
- 「輪郭と四角い境目を優先（低速）」：混色点模様を追加せず、タイルの形と隣接境界を評価する。元画像との差が増えすぎるコマでは通常の近似を維持。変換が遅くなるため既定OFF。16×16色属性・256パターンの制限は残る。
- 停止：正常終了時は待機画面へ。切断または3秒間の受信停止でも、受信途中のフレームを壊さず待機画面に戻り、音声リングを無音にする。これには受信ファームr2が必要。

## キーボード

ユーザーの [Famicom-Expand-USB-Adapter](https://github.com/SHIMA-R7/Famicom-Expand-USB-Adapter) のNano走査・Picoキー割り当てと、以前の `gen_remote_driver.py` / `KeyboardBridge` を照合して復帰した。列選択後500µs、各キー2回一致のチャタリング対策、SHIFT/GRPH/CTRのトグル、RETURNでSHIFT解除、STOP/DELのBackSpaceを維持。

旧USBリモート送信コードにはPC側のキー処理が残っていたが、安定動画用6502ドライバーから走査が省かれていた。今回は映像のPPU書き込みを終えた後に9行×2列を走査し、入力をFCINで送る。キーボードの抜き差しはFC OFFで行う。

## 音声と診断ログ

PC側の再サンプリングに、塊ごとに補間の開始点がずれる不具合を確認した。48kHzの2秒を32kHzへ変換する再現試験で、旧版は一括64000サンプルに対し20ms分割63934サンプルだった。修正版は両方64000で同じ波形になる。フィルター履歴と補間位相を別々に保持する。

受信側では、256msリングに余裕があるのに150msを超えた時点でパケットを捨てていた条件を変更し、パケット全体が安全な空き領域に入るかで判定する。PIO出力自体は維持。ノイズがすべて解消したという実機結果はまだない。

ログには入力音声の形式と、受信側の「受信パケット数／捨て数／不足回数／最大処理間隔」を出す。記録先は `%LOCALAPPDATA%/FC-MAGICON/usb-*.log`。ログの文字コードと逐次出力も明示した。

## 成果物と検証

- 受信：`firmware/out-standalone-video/remote-desktop-usb-a9-gpio39-20261017-r2.uf2`
- PC側：`firmware/tools/usb_sender.py`、`remote_pc.py`、`pcaudio.py`、`tile_seams.py`
- ビルド：`firmware/standalone_video/build.ps1 -Desktop`、`firmware/tools/build_usb_sender.ps1 -Python <Python>`
- 5種類の入力レート（24/32/44.1/48/96kHz）で不規則な分割と一括変換のサンプル数・位相一致を検査。
- 通常／中間／ズームの循環、画面端、追随OFF、小画面の取り込み範囲を検査。
- 実際の6502コード＋Cカート処理でパッド、全9行のキーボード、500µs待ち、7 VBlankの完成フレーム切替を検査。PPU最終書き込みは最大1586 CPUサイクル、NMI全体19304サイクルで次のフレームまでに復帰する。実機測定値ではない。
- 既存72キー割り当て／チャタリング／トグル／終了時キー解除の検査を通過。
- C側の画面・属性・高速パレット応答、表裏切替、待機画面の表示待ち保護を検査。

前版r1はユーザーがUSB映像・音声の成功を確認。r2のFMVと実機での聴感・キーボード・ゲーム入力は確認待ち。単独動画の完成版および+8MiBの動画データは保持する。

## 2026-10-18 ブルアカ入力診断 r2.3

「入力診断」ボタンで `%LOCALAPPDATA%/FC-MAGICON/input-diagnostics-*.json` を保存する。ブルアカを起動した状態で採取する。送信中はログに入力先プロセス名・整合性レベル・権限差を記録する。移動だけでなくクリック／キーもSendInputの戻り値を確認し、失敗をログに出す。診断版は入力拒否で直ちに終了せず、警告しながら転送を続ける。

通常のWindowsではFCパッドとNanoマウスが動くが、日本版ブルアカ上では両方の移動・クリックが効かないとの報告。このPCのゲームは起動しておらず、FMVの実権限もまだ未測定。手元のBlueArchive.exeのmanifestはasInvokerであり、それだけで管理者として動いていないとは判断できない。まず送信EXEを右クリック→管理者として実行した場合と比較する。自動昇格は行わない。

SendInputは高い整合性レベルのアプリへ注入できないが、戻り値・WinErrorだけではUIPIが原因とは特定できない。入力成功件数が1でもゲームが受理した証明にはならない。権限差で説明できなければ、入力先・ゲーム側の受付方式を次に確認する。Raw Input専用やアンチチートによる拒否とは断定していない。

受信r2は、送信アプリ終了時のFCST、および切断／受信停止約3秒で音声を止め待機画面へ戻す。r2.3でもこの停止仕様を利用できる。受信r1＋キーボード版には停止画面機能がない。
