# CHR読み出し照合診断

直前のNT読み戻し診断は実機で緑だった。今回は同じ静止画を一度だけ転送し、表示中のCHRバンク4096バイトをFCのPPU $2007から読み出す。期待値はCPU $7000〜$7FFFに公開したMCUの表示中CHR lookup値。CPU側の期待値取得とPPU側の実データ取得は別経路。

32バイトずつ128回のVBlankで照合。各区間でPPUADDRを設定し、遅延読み出しバッファ用の最初の$2007読みを捨てる。音声・連続転送は動かさない。

- 緑一色：CHR4096バイトが期待値と一致。
- 青一色：CHR読み出しに不一致。
- LED：一致は1回、不一致は2回の点滅を繰り返す。
- 判定まで約2.1秒＋初期起動時間。10秒経過しても診断完了が来なければ故障コード6。

緑でも、表示中の連続フェッチやフレーム更新時の負荷で正しく返せることまでは証明しない。青でも、PPUバス応答・アドレスサンプリング・期待値用CPU読み出し等のどれかと即断しない。

実C/6502命令とPPU遅延読みモデルで、正常ケース0不一致・緑、全4096バイトの取得値を意図的に変えるケース4096不一致・青を検証。最大NMI1789 CPUサイクル。結合UF2からのデータ復元一致も検証。

生成：`gen_video_driver.py baseline/chr_readback_driver.h --chr-readback`。

ビルド：`build.ps1 -ColdBoot -ChrReadback`。NT診断と別のROM・ビルドフォルダ・成果物を使う。

UF2：`firmware/out-standalone-video/chr-readback-cold-20261014.uf2`

SHA256：`90069920e7f42c7da941326bfc5a540b36f35ce3cc470c1aafb408acc301e879`

ユーザーのFC OFF・BOOTSEL接続確認後に書き込み。実機の判定結果は未確認。

## 初回実機結果

ユーザー報告は「灰色」、写真でも画面全体が灰色。定義した緑（比較一致）・青（不一致）のどちらでもないため、CHR比較の結果として扱わない。診断の起動・進行・結果描画のどこで停止したか未特定。基板LEDの点滅回数を確認中。

LEDが6回ならMCUが比較完了コードを10秒以内に受け取れていない。1回/2回ならMCUは一致/不一致の完了コードを受信したが、画面の判定色描画は別途失敗した可能性がある。他の回数ならmain.cの故障コードと照合する。点滅なしの場合もCHR不一致と即断しない。

追加確認でユーザーはLED「1回」と回答。一致判定コードをMCUが受信したと解釈する。灰色表示の理由は未解決。静止CHR読み戻しが一致したという結果を、連続更新中のフェッチ・判定色描画まで正常と拡張しない。
