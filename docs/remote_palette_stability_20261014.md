# 4fps映像のパレット安定化

前の完成後切替版は実機録画で改善が確認できたが、フレームごとに独立した色探索が青/灰などの揺れを作る。次のPC側変換では、4fps・120枚を色ヒストグラム差とRGB変化量で区切り、各区間の全フレームから共通の4組のパレットを選ぶ。同一区間のパレットは固定し、16×16領域の組選択はフレームごとに行う。組の選択には小さい空間平滑化罰点と前フレーム保持の罰点を加える。

背景候補4色、区間パレット探索10反復、ディザなし。色ヒストグラムL1差>0.45かつ平均RGB変化>18で区切る。今回32区間に分かれたが、この区切りが意味的な全場面転換と一致する保証はない。将来のライブ画面取り込み用ではなく、先読み可能な保存動画の実験変換。

結果（同じ120枚とのPC比較）:

| 指標 | 前版 | 今回 |
|---|---:|---:|
| 元画像に対する平均Lab二乗誤差 | 265.906 | 267.692 |
| 動きの小さい画素の時間方向誤差 | 1.855 | 1.402 |

時間方向誤差は、元画像の平均RGB変化が3未満の画素で、変換後Lab差分から元画像Lab差分を引いたベクトル長の平均。約24.4%減。静止画の色誤差は約0.67%増。知覚的な画質の総合点や実機のフリッカー測定ではない。

全120枚を256タイル以内へ近似し、実際のremote_full.hをコンパイルしたDLLの再構成RGBが送信画像と一致することを確認。ファームウェアは変更せず、実機で改善確認済みの完成後切替・PIO PCM版を使用する。

ソース: `firmware/tools/scene_palette.py`、`firmware/sim/retroarch-remote-20261013/prepare_stable_palette_clip.py`。

ローカル出力: `firmware/sim/retroarch-remote-20261013/youtube-U6Wlb18KLrI/quality-4fps-stable`。比較画像は左=元画像、中央=前版、右=今回。プレビューは変換結果を並べたもので実機録画ではない。プレビュー音声と実機再生は素材を20倍に増幅（クリップ0）。

4fps・音声付き30秒の実機転送が完了。ホスト提供120枚・最終書込120枚、4.0枚/秒。画質の実機確認はユーザーの評価待ち。
