# 表示安定化後のロードマップ

2026-10-15のユーザー方針。今後の優先順位を記録する。新たな作業開始・実機書き込みを指示したものとは扱わない。

1. 現在の表示崩れを解消し、NEWファミコン／ツインファミコン、電源投入の繰り返しで再現性を確認する。診断で最初だけ失敗する現象と、動画で崩れ続ける現象は分けて扱う。
2. リモートデスクトップを改善する。特にPC版ブルーアーカイブのプレイへ最適化する。
3. ESP32-C6経由の無線転送へ進む。帯域・バッファ容量と、電流・電圧・起動過渡・発熱・電源分離は別々に評価する。

## ブルーアーカイブ向けの候補

- PC全体の縮小ではなく、ゲーム領域だけを取り込む。
- 全体表示と、カーソル／操作箇所の拡大表示を切り替える。文字・スキル欄など読みたい領域へ画質を優先配分する。
- 場面転換では全体を更新し、通常時は変化領域を優先。照準中は遅延と更新頻度を優先し、静止画面では細部を優先する。
- 小さいカーソル、低い基本感度、押し続けた時の加速、ドラッグ保持、よく使う操作の割り当てを調整する。
- PC側の画面変換と通信の待ち行列を短くし、古い映像を捨てて最新フレームを優先する。音声バッファとの同期は別に管理する。
- PC側で実画面とFC用変換結果を並べて確認し、UIと操作を先に検証する。その後実機で見やすさ・遅延を評価する。

画面を256×240へ詰める際の16:9→4:3変形はユーザーが許容している。既存の4:3→16:9外部コンバーターも考慮し、一般的な縦横比維持へ勝手に戻さない。

## C6の見積もりと制約

既存system_specにはPC→Wi-Fi→C6→RP2350 USBホストの420KB/s測定記録がある。これは過去の条件の記録であり、現在の修正済み映像・音声と統合した実機結果ではない。

単独再生の最終レコード形式（5152バイト/枚）をライブ転送にも使うなら、8fps映像41216B/s＋PCM8モノラル32kHzの32000B/s＝73216B/s。ヘッダ・制御・再送分は別。従来ライブ形式は1枚約15463バイトなので、これと混同しない。帯域が余ってもCPU変換速度、フレーム更新の締切、ジッタ、入力遅延の余裕があるとは限らない。

EspressifはC6の単一電源について3.3V・供給能力500mA以上を推奨する。常時500mA消費する意味ではない。[公式設計ガイド](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32c6/schematic-checklist.html)。FC側へ追加される負荷は、実際のC6ボードのレギュレーターと電源経路、RP2350側と合わせて評価する。旧仕様書の「RPモジュールは数十～100mA程度」という見積もりをC6併用へ流用しない。

初期の無線検証ではC6側給電を分けた構成を候補とし、USB VBUS・共通GND・逆給電防止を含む接続を確認してから統合する。本体単独給電へまとめる判断は実測後に行う。

## 追加アイデア

- FC向けPCランチャー：大きい文字とアイコンでゲーム／動画／音楽を選ぶ。一般デスクトップより読みやすく操作しやすい入口。
- 操作箇所の拡大窓：画面全体を残しつつ、選択中のスキルや照準部分だけ拡大して確認する。
- 自律動画・音楽プレイヤー：プレイリスト、一時停止、選曲。容量は現在の媒体レイアウトと別途計算する。
- FCカメラ／写真モード：PCのカメラ画像や写真をFC向けに変換して保存・表示する。
- 文字専用リモート端末：ファミリーベーシックキーボードと組み合わせ、PC側の文字情報を画像縮小より鮮明・低帯域に送る。
- NSFと拡張音源：既存プレイヤーの未検証点を詰め、VRC6等の合成へ段階的に進む。
- 自己診断メニュー：本体別の設定、起動・バス・音声・通信の検査とログ採取をカセット上から選べるようにする。
