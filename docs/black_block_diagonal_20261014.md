# 4fps-3録画からの比較版

`ブルアカ7thPV-4fps-3.mp4`（27.58秒）を確認。録画開始〜約2.5秒はコンバーターの青画面であり、最初の同一フレーム区間全体は観察できない。録画約22〜24秒では同じ絵に黒い矩形が出入りし、約24.9秒以降は更新が止まり、矩形の出入りも止まる。色数制約だけでなく更新経路を調べる根拠になる。ただし原因の特定ではない。

## 修正した弱点

これまで裏ネームテーブルを$2400にしていた。$2000と$2400は垂直ミラーでは別だが、水平ミラーでは同じCIRAM領域になる。基板にはJP2の垂直固定・JP3の水平固定という選択肢がある。ユーザーの現物ジャンパー状態は未確認。

独立した2領域を水平・垂直の両方で確保するため、裏を$2C00に変更。PPUCTRLは裏表示時$91から$93へ、スクロール復帰時のPPUADDRも$2400から$2C00へ変更。CHRバンクの選択、映像レコード、音声、fps、転送量は変更しない。1画面ミラーや実配線不良まで解決する変更ではない。

## 検証

実際のC/6502テストに水平ミラーの物理アドレス変換を追加。修正前は非表示のはずの書き込みが表示側を変えて失敗することを確認。修正後は水平・垂直とも全96フレーム、7-VBlank切り替え、最大1779 CPUサイクルの検査が通過。実機用ビルド・結合UF2からの保存データ再構成一致も確認した。

`test_standalone_video.py <media> --cold --horizontal` が水平ミラー試験。従来のオプション省略時は垂直ミラー試験。

## 実機結果（4fps-4録画）

上記の比較版はユーザーのFC OFF・BOOTSEL確認後に書き込み、picotool照合と再起動を実施した。`ブルアカ7thPV-4fps-4.mp4`（27.92秒）を確認。黒い矩形の出入りは残り、約25.2秒以降の最終静止画にも大きな黒い矩形が固定されている。ユーザー報告も「あまり変わったようには見えない」。改善確認とは扱わない。

前回の「更新を止めると落ち着く」は、出入りが止まるという観察まで。正しい画像に戻ることを意味しない。今回の録画でその区別が明確になった。水平・垂直の領域重複対策はソフト上の弱点を解消するが、実機の主原因という仮説の優先度は下げる。

次の切り分けでは、FCのPPUから書き込んだネームテーブルを読み戻し、送信元データと一致するかを調べる。保存データの検査だけで実機の書き込み成功とはみなさない。読み戻し診断はまだ未実装であり、今回の観察だけでCIRAM・CHR・CPUバスのどれかに原因を断定しない。
