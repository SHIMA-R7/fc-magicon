# FC側で生成した固定パターンの読み書き診断

動画更新を止めた状態でもNT不一致が出るかを、画像データ読み出しから切り離して検査する。FCのCPUがパターンを生成してPPU $2007へ書き、同じ経路で読み戻して比較する。PRG命令の取得と結果メールボックスにはマジコンのCPU応答が必要なので、FCだけで完全に独立する試験ではない。

パターンは00、FF、55、AA、01、02、04、08、10、20、40、80、アドレス低位とページ値のXORの13種類。$2000と$2C00の各1024バイトへ互いに反転した値を書いた後、一方を4回読み戻す。両方のバンクを対象に2巡、計52試験。2バンクを先に書いてから読むことで、2つが同じメモリへ別名接続されている場合も検出する。

画面描画とNMIは無効。音声と動画の媒体読み込み・ステージ更新を開始しない。CHR描画のDMA応答は検査対象外。起動と電源OFF時の出力抑止は従来と同じで、電気的な未給電入力保護を追加する変更ではない。

各試験で不一致総数、最初のオフセット・期待値・実値、XORの累積、各データビットの不一致数を集計。32バイトの結果を連番とACKでRPへ渡し、全試験終了後にUSBを開始して繰り返し出力する。メールボックス破損・未完走も別に記録する。

LED：全試験合格1回、不一致2回、未完走／レポート整合性異常3回。画面は最終的に合格なら緑、不一致なら赤の単色を出す。起動やCPU命令取得自体が壊れた場合は、この表示まで到達しない可能性がある。

実Cバス処理と実6502プログラムのホスト検査：

- 正常：52試験、書き込み106496バイト、読み出し213200回（遅延バッファの捨て読みを含む）、不一致0。
- 読み出しD1ビットの0固定：同じ52試験で106496回の不一致。XORとビット別集計がD1だけを示すことを確認。
- 2バンクの別名接続：同じ52試験でバンク0のみ各4096回不一致、バンク1は一致することを確認。

これらは実機の信号、電圧、温度、PIO応答時間を検証したものではない。
