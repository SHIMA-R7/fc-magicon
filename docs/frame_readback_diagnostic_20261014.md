# フレームごとのNT読み戻し診断

ユーザー確認：静止NTは緑、静止CHRは灰色だがLED1回（一致コード）。次に各フレーム更新後のNTを調べる。

元PV21.25〜24.00秒の12枚を順に表示する。1枚ごとに7回のVBlankで更新し、その後32回のVBlankでNT・属性1024バイトを照合してから次へ進む。期待値を検査完了まで保持し、フレームごとに検査位置と不一致数を初期化する。不一致ならそのフレームで停止。

4fps再生そのものを維持したテストではない。読み戻しを挟むため1枚約0.65秒、全体約7.8秒＋起動時間。音声・音声DMAは停止。連続フェッチや通常4fpsの負荷を完全再現するテストではない。

今回はパレットを判定色で塗りつぶさず、画像をそのまま残す。

- 検査中：基板LED点灯。
- 全12枚一致：最後の画像で停止し、LED1回ずつ点滅。
- 不一致：そのフレームで停止し、LED2回ずつ点滅。
- LED6回：検査完了の待機期限超過。5回：次フレームの更新応答失敗。

実C/6502・PPU遅延読み出しモデルで12枚の交互バンク更新と各1024バイト照合が成功。各フレームの全NTバイトを意図的に破壊するテストでは、毎回1024不一致を検出し、検査位置・カウンターの再初期化も確認。最大NMI1800 CPUサイクル。ファームビルド・結合UF2からのデータ復元も成功。

`gen_video_driver.py baseline/frame_readback_driver.h --frame-readback`、`build.ps1 -ColdBoot -FrameReadback` で生成。別ビルドフォルダ・別成果物を使用する。

UF2：`firmware/out-standalone-video/frame-readback-cold-20261014.uf2`

SHA256：`bf86f5380c7552f114ec9ce676014a9421b4d63f8bad1fd1b2f64fc9f4064560`

ユーザーのBOOTSEL／FC OFF確認後、同じデバイスEF5E4EB554097CDFへ書き込み・picotool照合・アプリ再起動を実施。実機結果は未確認。

## 実機結果

ユーザー報告は「一回点滅」。写真では最後の元PV24.00秒の場面に大きな黒い矩形が残る。保存した同じフレームの参照画像にはその矩形がないことを目視確認した。

この診断条件では12枚すべてのNT・属性が期待値と一致した判定。通常4fpsの負荷条件まで正常と結論しない。黒い矩形は変換時から保存されていた形ではなく、まだ未検査のパレットや、実表示中のCHR取得等の経路を調べる。参照画像は `firmware/sim/standalone-video-20261014/frame-readback-final-reference.png`。
