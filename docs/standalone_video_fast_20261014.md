# CPU応答短縮を通常再生へ反映

パレット診断版で、同じ12枚のNT・パレット照合が全完走し、最終16色の保存元/FC期待値/PPU実値が一致した。ユーザー写真でも大きな黒い矩形の解消が確認できた。そのCPU応答処理を、通常30秒・4fps・音声付き再生版に反映する。

映像・音声データは既存の4:3補正済み `pv-30s-4fps-4x3.fcpv` と同一。診断中の長い読み戻し待ちはなくし、従来の音声サンプル時計による4fps再生へ戻す。USBは完全無効、パレットログ出力なし。

通常版の実C/6502テストで全120フレーム・7-VBlank切り替え・最大1779 CPUサイクル、音声リング・故障期限を検証。専用CPU経路の全アドレス選択/返却値/書き込み待ちガードの検査も通過。ビルド・結合UF2からの媒体データ再構成一致も確認済み。

ビルド：`build.ps1 -ColdBoot -FastReads`

UF2：`firmware/out-standalone-video/pv-30s-4fps-4x3-fast-cold-20261014.uf2`

SHA256：`367d12e8f95cf20dfb16dd37820971c5a2403d694fd388ff751adf30aa6b158b`

ユーザーがBOOTSEL／FC OFFを確認したため、EF5E4EB554097CDFへ書き込みを実施。診断成功と、通常4fps・音声同時再生の成功は別に確認する。PC非接続・FC本体給電からのコールド起動条件も引き続き別項目。

## 通常再生の実機確認

ユーザーの録画 `ブルアカ7thPV-4fps-5.mp4`（34.06秒、冒頭にコンバーター画面を含む）と「完璧と言っていいかも」という報告を受領。16時点のコンタクトシートで、以前の大きな黒い矩形やランダムな色化けが見られないことを確認した。減色・タイル近似による細部の省略は残るが、従来の表示破損とは区別する。音声の忠実度や同期は、この画像確認では測定していない。

確認画像：`firmware/sim/standalone-video-20261014/physical-4fps-5-contact.jpg`

このUF2を、30秒・4fpsの通常再生が実機で成功した基準版として保存する。同じ映像データに対するCPU読み出し応答の短縮が、実機の表示破損解消に有効だった。全編99秒・8fpsと、PC非接続・FC本体給電でのコールド起動は未確認。

## 全編99秒・8fps比較版の書き込み

同じ成功済みファームウェアと全編媒体を結合し、実C/6502テストで全792フレームを確認した。ユーザーの書き込み指示を受け、BOOTSEL状態の同一デバイスへ `pv-full-99s-8fps-4x3-fast-cold-20261014.uf2` を書き込み、picotoolの全領域照合OK後に再起動した。音声付き、媒体7,248,448バイト。SHA256は `46a2fc814dead00eea8140705279cb1bf3a2d2017f3914d1ed0da5caeb6f3da7`。実機の全編再生結果は確認待ち。
